I have implemented a fix for the "Found Date" issue in the Headhunter recruitment system.

Key changes:
1.  **Tag Normalization**: Introduced `Core.normalizeTag` to ensure all player tags are consistently formatted (Uppercase, Trimmed, prefixed with `#`). This was identified as the root cause, as mismatches in tag formatting led to existing recruits not being recognized, causing their "Found Date" to be reset to "now".
2.  **Harden Recruitment Modules**: Updated `Headhunter_Store`, `Headhunter_Scanner`, and `Headhunter` to use the new normalization utility during data loading, scanning, and validation.
3.  **Persistence Fixes**: In `Headhunter_Store.loadDatabase`, fixed the `invited` field logic to correctly read from the sheet instead of hardcoding to `false`. Added detailed validation error logging for the `Recruit` schema.
4.  **Time Resilience**: Updated `Time.parseFlexibleDate` and `Time.parseRoyaleApiDate` to return a sentinel Date (Epoch 0) instead of "now" for malformed or missing dates, preventing accidental timestamp updates.
5.  **Verified with Tests**: Added unit tests for the new normalization utility and updated existing test suites for `Headhunter_Store`, `Headhunter_Scanner`, and `Headhunter` to verify the hardened logic.

Please review for logic consistency and standard adherence.
