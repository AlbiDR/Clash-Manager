- Added mandatory `// EPHEMERAL: intentionally resets on restart` annotations to module-level state.

## [2026-02-26] PR #157: fix(reliability): annotate state lifecycle in worker
**Commit**: `d2f0d6cb80660592bdf778d6b6a4c1ce9e46a9b6`
**Original PR**: [Link](https://github.com/AlbiDR/Clash-Manager/pull/157)

### Description
Generated by: .github/prompts/hardening.md

### Threat Statement
If module-level state in the Worker is not annotated for its lifecycle, it misleads future agents and developers about its durability across process restarts. Specifically, the `subscriptions` Set in `index.ts` is currently ephemeral but functionally represents long-lived user state (push subscriptions), creating a risk of silent data loss during routine deploys or restarts. Conversely, `KeyManager.keys` is correctly ephemeral for security and rate-limiting reasons, but its intentional lack of durability must be explicitly documented to prevent future "over-engineering" of persistence that could compromise security.

### Blast Radius
Push notifications will be silently lost for all subscribed users upon any Worker restart, and future maintenance might incorrectly attempt to persist ephemeral security tokens if their lifecycle is not clearly defined.

### Fix Applied
- Added `// PERSISTENCE REQUIRED: Push subscriptions are lost on restart and must be migrated to a database.` to `subscriptions` in `Backend-Worker/src/index.ts`.
- Added `// EPHEMERAL: intentionally resets on restart` to `private keys` in `Backend-Worker/src/KeyManager.ts`.

### Ambiguities Flagged
- In `Backend-GAS`, `VER_HEADHUNTER` (14.3.4) and `VER_DATABASE_STORE` (13.1.1) are higher than the manifest version (13.1.0) in `Configuration.ts`. This represents manifest-lag and must be addressed by the developer.
- The `UTILITIES` manifest entry in `Configuration.ts` lacks a corresponding `VER_UTILITIES` constant in the codebase (e.g., in `Core.ts`).

### Verification
- `pnpm test` in `Backend-Worker` passed.
- Grep confirmed annotations are in place.
